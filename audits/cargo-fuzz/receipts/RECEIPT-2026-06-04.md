# cargo-fuzz receipt — 2026-06-04 — T23.cargo-fuzz.1 (bounded fuzz smoke)

> **Outcome: NOT a clean smoke.** 9/9 targets executed under libFuzzer for a bounded budget; **5 clean, 4
> crashed → 3 distinct panic sites**, preserved as findings F1–F3 and **NOT fixed here** (fixing is the
> follow-up campaign **T23.cargo-fuzz.2**). This moves `cargo-fuzz` from *scaffold-only* to **admitted
> bounded execution with real findings** — which is exactly what a fuzz smoke is for. It does **not** claim
> exhaustive parser safety; it proves the harnesses execute under adversarial mutation for the stated budget
> and that 3 panic-on-hostile-input sites exist.

## Toolchain (version-pinned)
- `cargo-fuzz 0.13.1` · `rustc 1.98.0-nightly (31a9463c6 2026-05-25)` · libFuzzer via `libfuzzer-sys 0.4.13`
  (ASan-instrumented; `-Cdebug-assertions` + the crate's `overflow-checks=true` ⇒ a wrap/overflow is a finding).
- Host: x86_64, Linux 7.0.9-1-cachyos. zic-rs: 0.1.0. Budget: **`-max_total_time=25` per target**, `-rss_limit_mb=4096`.
- Command (verbatim, per target): `cargo +nightly fuzz run <target> -- -max_total_time=25 -rss_limit_mb=4096 -print_final_stats=1`

## Finding F0 (config, fixed to enable the run) — stale fuzz dependency
The T17.FUZZ scaffold's `fuzz/Cargo.toml` had `tzcompile = { path = ".." }`, but the package was renamed
**`zic-rs`** for the crates.io publish (lib name kept `tzcompile`). cargo resolves deps by *package* name, so
the fuzz crate no longer built (`no matching package named tzcompile`). Fixed to
`tzcompile = { path = "..", package = "zic-rs" }` (depends on `zic-rs`, imported as `tzcompile` — every
target's `use tzcompile::…` unchanged). This is a build-config fix required to run at all, recorded transparently.

## Findings (preserved as regression seeds in `../findings/`; NOT fixed — owned by T23.cargo-fuzz.2)

- **F1 — single-`\n` TZif footer → slice-index panic.** `src/tzif/validate.rs:406` does
  `&tail[1..tail.len()-1]`. A `tail` of a *single* `\n` byte passes the preceding `tail[0]==b'\n' &&
  tail[last]==b'\n'` guard (the one byte is both first and last), then slices `[1..0]` → panic
  ("slice index starts at 1 but ends at 0"). Reached by **two** targets (`posix_footer`,
  `tzif_validate_bytes`) via a crafted TZif whose footer region is a lone `\n`. Seeds:
  `findings/F1-validate-footer-{posix_footer,tzif_validate_bytes}.bin`.
- **F2 — huge hour count → multiply-with-overflow panic.** `src/model/time.rs:96` computes
  `h * 3600 + m * 60 + sec`; the parser is *deliberately* lenient on the hour count (comment: "zic is lenient
  … it may exceed 24"), so a `Zone` offset like `-0000000006326386204529102403` overflows `h * 3600`.
  Because zic-rs sets `overflow-checks=true` in **all** profiles, this panics in release too (not merely a
  debug artifact). Seed: `findings/F2-time-multiply-overflow-release_diff_tree.bin`.
- **F3 — non-char-boundary `str` slice panic.** `src/source/parser.rs:345` (`strip_prefix_ci`) does
  `s[..prefix.len()]` after guarding only `s.len() >= prefix.len()` (byte length), so an input whose byte at
  `prefix.len()` is mid-UTF-8 (the seed embeds `\xd9\x8c`) slices on a non-char boundary → panic. Seed:
  `findings/F3-parser-char-boundary-zone_rule_link_parser.bin`.

## What this closes / qualifies (honest)

- **Closes:** the `cargo-fuzz` *scaffold-only* hole — the harnesses now have admitted bounded execution
  evidence, and the build-config rot (F0) is fixed.
- **QUALIFIES the panic-policy claim.** `docs/panic-policy.md` / `RISK` previously held *"no malformed/hostile
  input may panic; invalid input → typed `Err`."* The static `panic-analysis` audit (0 `panic!`, guarded
  `unwrap`/`expect`) **did not** reach these: F1/F3 are *implicit* panics (slice indexing / `str` slicing),
  F2 is an arithmetic-overflow panic — none is a literal `panic!`/`unwrap`, so a grep-based census missed all
  three. **Fuzzing found what static analysis could not.** Until T23.cargo-fuzz.2 fixes them, the panic-policy
  claim is **qualified: three known panic-on-hostile-input sites (F1–F3) exist.** This must read loudly, not
  be buried — it is the receipt earning its keep.

## Gate
The `fuzz/` crate is detached (empty `[workspace]`; not a parent dependency), and this campaign touched **no
parent `src/`** — only `fuzz/Cargo.toml` (F0), `audits/`, and docs. So the parent gate (fmt · clippy `-D
warnings` · 489 tests · CORE.1 341/0/0) is unaffected and unchanged from the last seal. The three findings
live in zic-rs `src/` and are addressed in **T23.cargo-fuzz.2**, where each fix lands with the preserved seed
as a regression test.
