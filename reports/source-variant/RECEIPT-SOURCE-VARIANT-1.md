> profile, with unsupported or deferred profiles named rather than hidden.*

## The question it answers

After 276/276 stable releases replayed under explicit modes, the remaining parity question is no longer "does
history replay?" but **"which source *profile* did you replay, and do the other valid tzdb profiles match
too?"** The tzdb source can be encoded/assembled several ways — `DATAFORM` (main / vanguard / rearguard),
`PACKRATDATA`/`PACKRATLIST` (backzone inclusion). This receipt runs **both** reference `zic` and zic-rs across
them and classifies each.

### Two corroborating invariants

- **Cross-encoding sanity (reference):** reference `zic` on `main` == `vanguard` == `rearguard` (behaviour) for
  every checked zone — confirming the three `DATAFORM` encodings are genuinely the *same data*.
- **zic-rs normalizes the encodings:** zic-rs's **output is byte-identical** across `main`/`vanguard`/
  `rearguard` for every zone — it correctly treats the three encodings as one dataset, regardless of whether
  the source uses negative SAVE (`vanguard`) or expands it to nonnegative explicit rules (`rearguard`). This
  is the real parity win: **zic-rs is not main-only — it handles vanguard's newest forms and rearguard's
  oldest-compatible expansion identically.**
- **Backzone-sensitive zone:** `America/Montreal` (whose content differs once backzone is merged) matches
  reference under `backzone_included` — the PACKRATDATA path is behaviour-correct.
