# T12 — close receipt (build-profile parity / manifest identity arc)

> **Status: T12 CLOSED.** This is a *documentation/doctrine* receipt. It records the senior invariants
> that emerged from the T12.5 source-variant arc so future work cannot lose the evidence boundaries
> that made T12 trustworthy. **It changes no compiler behaviour, no manifest schema, no report schema,
> and no source-variant semantics.** The last code+schema work was T12.5d (`DATAFORM`, schema `…-v8`);
> the gate at that point — `fmt` · `clippy --all-targets -D warnings` · **319 tests** · `doc` ·
> **CORE.1 341/0/0** — is unchanged by this doc-only close.

## 0. What T12 built (the arc, in one view)

| Sub-arc | What it closed | Where the evidence lives |
|---------|----------------|--------------------------|
| **T12.1–T12.3** | manifest *identity*: detected-vs-claimed tzdb version + a real `build_profile`; ordered `source_inputs` (per-file hashes + order-sensitive `aggregate_hash`) | `tzdb`, `build_profile`, `source_inputs` |
| **T12.4a–d** | link/alias identity + `backward` membership evidence; `AliasMap::validate()` fail-closed | `link_profile`, `source_profile.backward_evidence` |
| **T12.5a–a.3** | source-variant policy inventory + the reference-pin gate + signature-verified, hash-pinned **tzdb 2026b** admission + the all-IANA release-admission matrix | `reports/t12_5a1-…`, `reports/t12_5a2-…`, `docs/build-profile-parity.md` |
| **T12.5b** | `backzone` (`PACKRATDATA`) **membership** evidence, hash-anchored to the pinned 2026b `backzone` | `source_profile.backzone_evidence` |
| **T12.5c** | `PACKRATLIST` backzone-**scope** evidence, from an admitted *generation-policy* input only (the category-boundary correction: `zone.tab` is not a compile source) | `source_profile.packratlist_evidence` |
| **T12.5d** | `DATAFORM` **encoding** evidence, hash-matched against the pinned `main`/`vanguard`/`rearguard.zi` artifacts via `source_inputs` (category-correct — the `.zi` *are* compile sources), + `recipe_hash`/`generated_from` | `source_profile.dataform_evidence` |
| **T12.6** | static provenance/gate block surfaced in `support-report`/`structural-report` | report JSON `provenance` |

**The architectural win (not just accumulated fields):** the manifest model was *corrected* until each
fact lives in the right place. As of T12.5d, **`build_profile` carries zero source-variant
placeholders** — every membership/encoding axis is a `source_profile` evidence axis. `build_profile`
describes *how this run emitted*; `source_profile` describes *what the source was* (each a
hash-backed/claim-only `detected`/`claimed`/`status` axis, never a boolean).

The central rule:

> **Every byte and every claim must belong to the right evidence category.**

## 1. Humble invariants (binding doctrine for post-T12 work)

- admitted for 2026b, not all releases;
- evidence, not behaviour;
- manifest provenance, not TZif semantics;
- hash-backed, not guessed;
- generated by a pinned recipe, not magic;
- a warning class, not exact wording yet;
- pristine-upstream, not distro-patched;
- release-admitted, not inferred;
- category-correct, not merely convenient;
- `unknown` is honest when evidence is insufficient.

These are project constraints, not slogans: they prevent zic-rs from converting weak observations into
official-looking claims.

## 2. Evidence-category taxonomy (the spine)

T12.5c exposed the founding category error — `zone.tab` is a generation-*policy* input, not a `zic`
*compile* source. T12-close generalises it. Every byte/artifact is classified under exactly one:

| Category | What it is | Example | Manifest home |
|----------|-----------|---------|---------------|
| **`compile_input`** | a `zic` source that participates in compilation | `tzdata.zi`, `main.zi`, `vanguard.zi`, `rearguard.zi`, `backzone` (when admitted) | `source_inputs` |
| **`policy_input`** | a generation-time *selector* applied *before* `zic` | `zone.tab` / `PACKRATLIST`, `PACKRATDATA`, `DATAFORM` policy, Makefile knobs | `packratlist_evidence` (admitted only) |
| **`reference_input`** | an admitted + pinned upstream byte set | `tzdb-2026b.tar.lz`, `Makefile`, `theory.html`, `backward`, `backzone`, `zone.tab`, `zone1970.tab`, `leapseconds`, `ziguard.awk` | `reports/t12_5a2-…` |
| **`generated_artifact`** | output of a pinned generation recipe | `main`/`vanguard`/`rearguard.zi` | `dataform_evidence` (+ `recipe_hash`) |
| **`output_artifact`** | what zic-rs emits | TZif files, alias-map, compile manifest, support/structural reports | the output tree / report files |
| **`diagnostic_artifact`** | warnings/errors/classes/locations | `ZIC001`…, `zic -v` parity (T13) | T13 surface |
| **`policy_prose`** | non-compiling policy text that still shapes generation | `Makefile` comments, `theory.html` | release-delta review |
| **`release_note_evidence`** | change descriptions across releases | `NEWS`, release announcements | release-delta review |

**Category-correct invariants (binding):** `zone.tab` is `policy_input`, not `compile_input` ·
`backzone` is source-membership evidence, not behaviour · `vanguard.zi`/`main.zi`/`rearguard.zi` are
`generated_artifact` evidence, not universal DATAFORM truth · diagnostics are compatibility output, not
UX copy · the **manifest is provenance, not TZif semantics** · dirty local tzdata is distro/local
evidence, not pristine upstream.

## 3. Era-aware release-admission states

The all-IANA matrix classifies every admitted source by provenance class:
`upstream_pristine` · `upstream_generated` (the `ziguard.awk` `.zi`) · `distro_patched` ·
`local_dirty` · `unknown`. The installed **`2026b-dirty`** observed in T12.5a.2 is **`local_dirty`, not
"bad"** — a different provenance *class*, not a failure. Feature axes additionally distinguish
**`not_applicable`** (the release predates the axis) from **`unknown`** (the axis exists for this era
but no evidence was admitted).

## 4. Current-release-bias guard

2026b's `Makefile`/defaults/generated files/source-variant policy define the *first* pinned profile —
**not an eternal one**. zic-rs must not assume older or future releases share the same axes, generated
files, defaults, or Makefile semantics. *2026b is admitted; other releases are admissible by the same
ceremony; no release is supported by inference from another.*

## 5. Standard-boundary doctrine (RFC 9636)

TZif output is governed by **RFC 9636**. The zic-rs manifest, `source_profile`, build/link/report
blocks, and release-admission receipts are **provenance artifacts, not required TZif sidecars** — a
TZif consumer must interpret the emitted bytes **without** any manifest. Manifest provenance is not
TZif semantics; release admission does not alter the TZif format. Future TZif structural validation is
T14/T15 (§19), not T12-close.

## 6. Reproducibility doctrine (generalises the T12.5d `recipe_hash`)

Every *generated* reference artifact must be described by recipe, not treated as magic — recording:
source archive hash · generator-file hash · generation command · tool versions · environment
assumptions · raw output-artifact hash · `recipe_hash`. **`recipe_hash` hashes raw bytes and recorded
recipe material; it must never line-ending-normalize upstream inputs before hashing.** T12.5d applies
this to `main`/`vanguard`/`rearguard.zi`; the same doctrine binds any future generated input.

## 7. Source-hash classes

Don't assume one file per semantic role forever. Distinguish: `standalone_file_hash` ·
`concatenated_input_hash` · `generated_artifact_hash` · `extracted_member_hash` · `output_artifact_hash`
· `diagnostic_artifact_hash`. tzdb material appears as standalone files, concatenated `.zi`, generated
artifacts, extracted archive members, or downstream-patched local files.

## 8. `source_origin` model (incl. stdin)

A compile manifest must not pretend every input has a stable filesystem path. The future model
distinguishes `source_origin ∈ {path, stdin, generated, admitted_reference, policy_input}`. If stdin
(`-`, per `zic(8)`) is supported it is recorded as `path="-"`, `display_name="<stdin>"`,
`content_sha256=…`, locations `stdin:line:col`. **stdin is currently a documented non-capability**
(not a claimed input) until implemented — owning milestone **T16** (release-ecology / source identity).

## 9. Negative capabilities (restraint as visible engineering)

The standing list of what zic-rs explicitly does **not** infer or claim — guaranteed by construction
(reconcilers read only file hashes / admitted claims) and guarded by tests:

```text
does_not_infer_backward_from_aliases
does_not_infer_backzone_from_output_shape
does_not_infer_PACKRATLIST_from_zone_counts
does_not_infer_PACKRATLIST_from_output_shape
does_not_infer_DATAFORM_from_content
does_not_infer_DATAFORM_from_negative_SAVE
does_not_require_manifest_to_read_TZif
does_not_claim_all_IANA_releases_without_admission
does_not_treat_dirty_local_tzdata_as_pristine_upstream
does_not_claim_source_variant_behavior_implemented
```

`source_variant_behavior_implemented` stays **`false`** — T12 is evidence modelling, not behaviour; it
flips to `true` only if a future milestone actually changes compiler/output behaviour for a variant.
**Assigned commitment:** surfacing this list as a `negative_capabilities` array in
`support-report --format json` (with the one-line machine-readable status) is committed to **T15** —
recorded here as doctrine, owned there as a deliverable (not a vague deferral).

## 10. Release-delta review requirement (for future tzdb admissions)

A new IANA release must **not** be admitted by file hashes alone. Before admission, zic-rs reviews and
records: `NEWS` changes · `Makefile` diff · `ziguard.awk` diff · `backward` diff · `backzone` diff ·
`zone.tab`/`zone1970.tab` diff · `leapseconds` diff · new/removed policy axes · warning/diagnostic
behaviour changes · generated-artifact recipe changes. The result produces a
**`release_delta_review_hash`** — a SHA-256 over the *reviewed delta receipt* (curated review notes +
the set of file hashes compared), **not** merely the file hashes. This binds "we reviewed what
changed", and prevents silently universalising the previously admitted release. Owning milestone:
**T16** (release ecology), gated by the T12.5a.1 reference-pin discipline.

## 11. Reference-platform distinction

The **upstream IANA reference is the primary oracle**; vendor/platform behaviour is a separate axis.
Future docs/reports distinguish `reference_platform ∈ {upstream_iana, linux_glibc, bsd, macos, aix,
other_vendor}` (e.g. the AIX 32-bit `time_t` pre-1901 note). Don't assume one vendor manpage or one
platform build captures all behaviour. Owning milestones: **T13** (diagnostics) / **T16** (ecology).

## 12. Source comments as policy evidence

Comments usually don't compile into TZif, but some prose is evidence. Distinguish `semantic_source`
(Rule/Zone/Link) · `policy_prose` (`Makefile` comments) · `release_note_evidence` (`NEWS`) ·
`non_semantic_commentary` (ordinary source comments, unless explicitly cited). Supports release-delta
review (§10).

## 13. Public-domain ≠ no-provenance

tzdb being public-domain-like does **not** remove the need for authenticity, reproducibility, version
scoping, and patch provenance. zic-rs still records source URL · archive hash · signature status ·
extracted-member hashes · generated-artifact recipes · release-delta review.

## 14b. Non-reopen clause

**T12 may be reopened only for** (a) a *defect in the recorded T12 evidence model* (a reconciler that
mis-classifies, an axis in the wrong category, a hash anchored to the wrong reference) or (b) a
*stale-current-state correction* (a doc/schema-version drift). **New tooling named in §14 belongs to
its assigned later milestone and must NOT be backported into T12** — no "one more provenance note"
reopens the arc. Anything genuinely new (a behaviour, a new evidence axis, a validator) is a later
milestone, not a T12 amendment.

## 15. T12-close non-behaviour statement

T12-close does **not**: change compiler behaviour · change the manifest schema · change report schemas
· implement new source-variant behaviour · implement DATAFORM conversion · implement PACKRATLIST build
behaviour · implement TZif validation · implement warning parity · claim all-IANA support.

## 16. Handoff to T13

T13 is **warning & diagnostic parity** — a *compatibility surface*, not UX polish. Compare **by error
layer first** — lexical → structural → semantic → warning — matching **class + source location** vs
`zic -v`; **exact wording is a late goal** (it drifts across releases and vendor builds). Abbreviation
policy is a compatibility-diagnostic surface, not cosmetic. The layer-2 *tooling* (input-text
admissibility layer, metamorphic source-ordering suite, pathology ledger, hostile-output TOCTOU notes,
`zdump` semantic-witness tests, oracle-availability policy) is **reserved for T14/T15**.
