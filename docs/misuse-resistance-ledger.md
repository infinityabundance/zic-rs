# Misuse-resistance ledger (T19)

> How zic-rs's CLI/report **design** prevents a user from accidentally believing something false. Each row:
> the **misuse**, its **dangerous consequence**, the **guard** that resists it, the **test/proof**, the
> **report field** that makes the truth visible, and the **non-claim** it ties to. This is the
> design-as-safety-boundary view (cf. `rustls`'s safe-defaults posture); it pairs with `docs/risk-register.md`
> (the failure modes) and `TRUST.md` (the front door).

| Misuse (what a user might assume) | Dangerous consequence | Guard (design resists it) | Test / proof | Report field that shows the truth | Non-claim |
|---|---|---|---|---|---|
| treating `doctor` exit 0 as "host tools are present & correct" | trusts an absent/old/unreadable tool | `doctor` is **always exit 0** (diagnosis, not gate); each tool is a typed `ToolStatus` | `tests/doctor.rs` | `version_status` (`unsupported`/`command_failed`/`not_run`) · `hash_status` | tool presence ≠ correctness ≠ admitted reference |
| treating `release-diff` "exit 0 / no rows" as "releases identical / safe" | skips review of a real change | witness, not gate: exit 0 even with differences; absent oracle ⇒ `behaviour_unassessed` (never "no change") | `tests/release_diff.rs` (`…_behaviour_unassessed`, split-seam) | `oracle_mode` · `ReleaseChangeKind` · `behaviour_error` (`OracleFailureScope`) | unassessed ≠ unchanged |
| treating any report as a signed certification | propagates an unverified claim | `ReportProvenance = unsigned_local_report`; `declared_scope_hash` bounds the claim envelope | `tests/conformance_golden.rs` | `report_provenance` · `conformance_status` (bounded, no `compatible`) | report ≠ attestation (`RISK.REPORT.1`) |
| reading `tzif-validate` "conformant" as "semantically correct" | ships a structurally-valid-but-wrong TZif | five **separate** verdicts, never one `valid:true`; structural ≠ semantic stated in-report | `rfc9636` tests | `tzif_structural_verdict` + 4 others · `VALID_DISAMBIGUATION` | structural validity ≠ semantic parity (`RISK.TZIF.1`) |
| reading one vendor receipt as "this OS family behaves like X" | wrong portability assumption | receipts are immutable, per-platform, admitted by rule (`admit()` recomputes; producer self-assessment ignored) | `tests/vendor_oracle_receipt.rs` | `class_location_verdicts` · `known_divergences` · `receipt_production_mode` | a receipt is one ecology, not a family theorem (`RISK.VENDOR.1`) |
| reading "rejects the corpus" as "diagnostic parity" | test passes on exit code; class fidelity lost | verdicts compare **class + location**, not exit code | `tests/diagnostic_parity.rs` | per-fixture `class_location_match` vs `divergence` | safe rejection ≠ diagnostic-class parity (`RISK.DIAG.1`) |
| aliasing `zic`→`zic-rs` | the invocation breaks (subcommands, required `--out`) | deliberate subcommand CLI; no implicit system install | `tests/cli_operational_parity.rs` | the 0/1/2 exit contract | not an argv drop-in (`docs/drop-in-compatibility-contract.md`) |
| assuming the default output is byte-identical to `zic` | byte-diff surprises a reader expecting slim | default is **fat-style** (behaviour-matched); slim is explicit (`-b slim`/`--emit-style`) | `tests/emit_style.rs` | manifest `build_profile.emit_style` | byte parity only in slim/where pinned |
| assuming the install is crash-durable for the whole tree | data loss on power-loss mid-run | per-file durable publish (Unix); whole-tree atomicity refused | `fs::output_tree::tests` | `install-materialization-contract.md` | no whole-tree crash-atomic install (`RISK.INSTALL.1`) |
| feeding a huge/hostile `.zi` and expecting graceful handling | OOM / panic / DoS | `limits::ResourceLimits` caps + checked count arithmetic + bounds-guarded parse | `src/limits.rs` tests · `tzif::validate` tests | `Error::config` (cap breach) — not a `ZIC###` | counts hostile until checked (`RISK.COUNT.1`/`RESOURCE.1`) |
| treating a bounded fuzz smoke as "exhaustively fuzzed" | false assurance | T23.cargo-fuzz.1/.2 ran a *bounded* smoke (found+fixed F1–F3); panic-policy restored only for the known seeds + that rerun | `audits/cargo-fuzz/receipts/RECEIPT-2026-06-04*.md` · `fuzz/receipts/RUNS.md` | the receipts | bounded smoke ≠ coverage-saturating campaign |
| treating `support-report` 0/"ran" as "fully `zic`-compatible" | over-adoption | bounded `conformance_status` (`release_admitted_compile_coverage`, never `compatible`) + `negative_capabilities` | `tests/conformance_*` | `conformance_status` · `negative_capabilities` (each `enforced_by`) | not universal parity (`RISK.ADOPT.1`) |
| citing a vendor doc as proof of measured behaviour | asserts unmeasured behaviour | the knowledge index separates `vendor_documentation` (context) from `reproducible_lab_evidence` (proof) | `docs/claim-source-map.md` | the source's `evidence_strength` tier | context ≠ proof (`RISK.SOURCE.1`) |
| treating a TZ **abbreviation** (`CST`, `IST`, …) as a unique zone identifier | wrong zone selected from an ambiguous label | zic-rs compiles abbreviations as *observed labels*, never as identity/canonicalization keys (the `AbbreviationIdentityPolicy` boundary) | `tzif-validate` / `semantic-report` rows carry the abbrev as data, not as a key | abbreviations are ambiguous (`tz-link` S13); not globally unique IDs |
| reading the POSIX `TZ`-footer offset sign as a normal numeric-offset sign | inverted far-future projection | the footer is parsed/emitted under POSIX's **opposite** sign convention, kept separate from human offset labels | the `posix_footer` surface · `structural-report` | POSIX `TZ` sign ≠ numeric offset sign (`tz-link` S13 notation trap) |
| treating TZif bytes or `bundle_hash` as **transport/distribution integrity** | a tampered/MITM'd bundle trusted because "the hash matched" | `bundle_hash` is a **local determinism witness** (artifact identity for reproducibility), not a signature; TZif itself carries no integrity protection (RFC 9636 §security) — distribution integrity needs an **external** signature/channel | `docs/perf-ledger.md` (bundle_hash = determinism anchor) · `docs/security-rewrite-evaluation.md` §D (signing **planned**, not present) | `bundle_hash` ≠ transport integrity; no SBOM/SLSA/signed release is claimed |
| reading a passing `tzif-validate` (or a slice-safe parse) as **RFC 9636 format validity** | a structurally-invalid-but-in-bounds TZif treated as conformant | the parser is memory-safe-*lenient* (e.g. `desigidx == charcnt`, `isdst == 2` don't reject); RFC structural validity is the `rfc9636` validator's job, and several byte-level RFC rules are **tracked gaps** | `audits/claim-boundary-map.md` (the standards-precision rows) · `tzif-validate` (5 separate verdicts) | memory-safe acceptance ≠ format-valid acceptance ≠ semantic parity |

## Doctrine

The recurring design move: **make the safe reading the default reading.** A report command's exit 0 means
*"it ran,"* never *"all clear"*; an absent oracle is *visible*, never silent; an unverified value is a
*typed unknown*, never a confident guess; a refusal is a *located non-claim*, never an omission. The
ledger exists so that a future reviewer can see the misuse was **anticipated and structurally resisted**,
not merely warned against in prose.
